# 更新日志

本文件记录这个插件对外可见的变化。

格式参考 [Keep a Changelog](https://keepachangelog.com/zh-CN/1.1.0/)，
版本号遵循 [语义化版本](https://semver.org/lang/zh-CN/)。

## [0.3.3] - 2026-10-25

### 修正

- **微信换票补齐请求字段。** `login_info` 里除了 `code` 还必须带 `appid`、
  `check_third_type`、`wx_info_type`，外层要用**微信渠道**的 `mcode`
  （`69028af6…`，跟 QQ 的 `132f0a77…` 不是一个值）。此前只传 `code`，
  扫码授权成功后换票必然失败，回 `result=2025` + 内层 `code:10002`，
  看着像「授权码无效」，实际是少传了参数。

### 变更

- 图标源图移出仓库，`test_metadata` 改为断言根目录只有 `logo.png`；
  `docs/RELEASING.md` 里的更换流程同步。

## [0.3.2] - 2026-10-25

### 变更

- 换票失败时把整个响应体写进日志（脱敏、截断）。微信换票回的 `2025` 没见过，
  `err_msg` 又只是把码复述一遍，只有完整响应里可能带线索。

## [0.3.1] - 2026-10-25

### 修正

- **失败时把腾讯的原话留下来。** 之前只记 `result=`，遇到没见过的码（比如微信
  换票的 `2025`）就完全无从下手，只能拿真凭据重放一遍。现在日志尾巴与服务端
  返回里都带上 `err_msg`，超过 40 字符的票据类长串统一抹成 `<长串>`。
- **换票失败不再被说成「登录态失效」。** 换票是去拿登录态的那一步，此时还没有
  登录态可言；之前因为它的 `err_msg` 里有 `login` 字样，被 `_是登录问题` 判成
  过期，让用户白扫一遍码。现在这一步的失败一律按业务错误处理。

## [0.3.0] - 2026-10-25

### 新增

- **`/爱瓦 绑定微信`。** 账号在微信区的用户以前根本用不了这个插件——掌瓦的
  QQ 扫码登录看不到微信区的角色。现在多了一条微信扫码路径，全程 HTTP，
  不需要浏览器侧车：
  1. `POST /go/auth/get_sdk_ticket` 拿 SDK 票据（不需要任何参数，也不需要登录态）；
  2. 微信 `connect/sdk/qrconnect` 用票据换二维码（appid `wxcbb49f1f39656c2a`）；
  3. 长轮询 `connect/l/qrconnect` 取授权码；
  4. `POST /go/auth/login_by_wechat` 用授权码换 `userId` / `tid`。
- 两条绑定路径共用落库与文案；`/爱瓦 绑定` 仍然是 QQ 扫码。

### 变更

- 凭据必备字段从 `openid + access_token + userId + tid` 收紧到 `userId + tid`：
  微信登录的返回里不一定带前两项。
- Cookie 里的 `acctype` 按凭据走（`qc` / `wx`），不再写死。

## [0.2.9] - 2026-10-19

### 修正

- **按游戏名挑端游角色。** 同一账号下「无畏契约」与「无畏契约手游」两个角色都会
  从主角色接口返回，而且顺序不固定。取到手游角色去查战绩，接口回
  `result=1003 err_msg='invalid scene game_id'`，被当成登录态失效，用户反复重绑
  也没用。现在按 `gameName == "无畏契约"` 选，没有端游角色才退回第一个；
  角色列表为空时直接说明「没返回游戏角色」，不再拿空参数去请求。
- `_是登录问题` / `_翻译错误` 认 `invalid scene`，归到「查错了角色」，
  不再翻译成「请重新扫码」。

### 变更

- 过期提示改成票据有效期：「掌瓦的登录态大约三天到期」（实测
  `validTo - validFrom = 259200`），并去掉之前「同一账号只允许一处在线」的说法。

## [0.2.8] - 2026-10-18

### 修正

- **登录态失效过之后，状态不再报「绑定正常」。** 重绑后的头几分钟，新旧会话在
  服务端交替生效，同一个号会几秒内时好时坏（实测 00:39:35 失效、00:40:44 成功、
  7 秒后又失效）。状态和绑定只发一次请求，撞上「好窗口」就给出假绿灯。
  现在凭据里记「最近失效」时间戳（30 分钟窗口），成功取到数据才抹掉；
  状态与绑定先看这个记录，命中就直接说失效，不再打接口碰运气。
- **绑定不再拦着重扫。** 刚失效过时 `/爱瓦 绑定` 直接允许覆盖重登，
  不会先回一句「已经绑定了，换号先解绑」。
- 顺手记一条实测结论：`get_main_role_raw` 在票据过期时回 `result=999999` +
  `DecodeTgpTicket`，是唯一能明确报「票据到期」的接口；`record/list` 在过渡期
  只会回 1003。两者配合才分得清「真过期」和「刚重绑的抖动」。

### 变更

- 业务取数统一走 `_取对局记账`，成败只在这一个地方记录，调用点不必各记一遍。
- 设置固定有效期的实测值：掌瓦登录态 3 天（`validTo - validFrom = 259200`）。

## [0.2.7] - 2026-10-17

### 安全

- **登录跳转加 host 白名单。** `_追跳转` 原来跟着 `Location` / 正文里的下一跳
  无条件走，会话里带着 cookie——跳到任意域等于把登录态交出去。现在只跟
  `*.qq.com`，其余一律断链并记一条轨迹；相对地址先补成绝对地址再判域。
- `connect.qq.com` 的三处 `http://` 改成 `https://`。
- **解绑时清掉 `.json.tmp`。** 写盘是「先写临时文件再 `os.replace`」，
  中途崩掉会留一份完整凭据；现在删除凭据时一并清掉。

### 修正

- **昵称过滤控制字符。** 换行能伪造提示词行、零宽字符能让两个名字看起来一样。
  写入与拼提示词前各过滤一次。
- `MessageEventResult` 改从 `astrbot.api.event` 取，不再走私有模块路径。

### 新增

- **配置项**（AstrBot 插件配置页可见）：接口超时、模型超时、允许 PK。
  三项都已接线，不是摆设；PK 关掉后只回一句「PK 已关闭」。
- README 增加「会连哪些地址」表，把 7 个域名全列出来。

## [0.2.6] - 2026-10-17

### 修正

- **日志不再打印请求体里的凭据。** 换票请求体的 `login_info` 里有 openid 与
  sig（sig 就是 access_token），原来 `_体摘要` 对 dict 直接 `repr`，整段明文进了
  INFO 日志。现在只打字段名，一个值都不打。
- **登录跳转轨迹脱敏。** `keystr` / `ptsigx` / `code` / `access_token` /
  `openid` 等参数一律替换成 `<redacted>`；回调地址、响应正文摘要、`最近原文`
  都过一遍 `脱敏()`。
- 删掉轨迹里的 `openid` 前 8 位——审核把「token 片段」也算泄漏。

## [0.2.5] - 2026-10-17

### 修正

- **数据目录改用插件名。** 市场审核驳回：规则是 `data/plugin_data/<plugin_name>`，
  `<plugin_name>` 指插件目录名，原来用的是 `plugin_data/aiva`。现在走
  `StarTools.get_data_dir("astrbot_plugin_aiva")`。老目录里的凭据在首次启动时
  自动搬过去（只搬不覆盖），搬完删掉空目录，用户不用重新绑定。
- **恢复 TLS 证书校验。** `aiva/transport.py` 原来用 `CERT_NONE` 关掉校验，
  而请求里带 openid / access_token / tid，等于把这些交给中间人。现在用 aiohttp
  默认上下文（校验证书链与主机名）；容器缺 CA 请装 `ca-certificates`，
  不要全局降级。

## [0.2.4] - 2026-10-17

## [0.2.0] - 2026-10-14

这一版几乎全是线上踩出来的修正。0.1.0 只跑通过绑定与战绩，其余指令首次
真正被人用时才暴露问题。

### 修正

- **段位不再被编造。** 提示词要求「称号里带段位」，但段位（`tier_text`）只在
  主角色接口里，对局列表没有——模型拿不到就自己编了一个（钻石玩家被评成
  「铂金」，编得还很合理所以没人当场发现）。现在 `取对局()` 一并把角色返回，
  段位写在喂给模型的文本**首行**；取不到就明写「接口没给，不许提段位」。
- **状态指令不再给假绿灯。** 以前只查 `get_main_role_raw`，而那个接口只要
  Cookie 形状对就回 `result=0`，过期了照样回 0；真正需要登录态的
  `record/list` 早就 1003 了。于是出现「状态说绑定正常、转头锐评说登录态
  失效」，两句都是真话。现在状态会额外打一次战绩接口。
- **登录态过期后可直接重绑。** 以前战绩说「请重新绑定」，绑定却说
  「你已经绑定了，要换号先解绑」，用户被两边踢皮球而没人告诉他要先解绑。
  现在绑定指令先真查一次登录态，死了就允许直接覆盖重扫。
- **模型调用不再无限等。** `tool_loop_agent` 会把当前会话挂着的全部工具
  schema 塞进请求（这台机器十几个插件），锐评实测稳定卡死 90 秒以上，
  而同一 key 同一模型直连只要 12 秒。改成直接调 provider 的 `text_chat`
  （这些指令一个工具都不需要），带 90 秒超时并把重试压到 1 次；超时后
  换新请求再试一次——挂起的连接不会自己恢复。
- **PK 认人改成按昵称。** QQ 官方机器人**收不到 @别人**：实测
  `raw_message.mentions` 是空数组，组件链里只有 @机器人 一个，`message_str`
  里被 @ 的人连文本都没留下。现在绑定时记昵称，用 `/爱瓦 PK 群友昵称`
  模糊匹配；重名时列出候选让用户选，不自动挑第一个。
- **修掉协程对象混进提示词。** `_名字` 体内没有 await 却写成 async，调用点
  漏 await 后拿到协程对象（它是真值，`or "你"` 兜底不触发），f-string 渲染成
  `<coroutine object Main.名字 at 0x...>` 被当成玩家名字喂给模型，模型还
  一本正经点评了它。`_名字` 改回同步函数。
- **错误不再是黑箱。** 业务接口失败时消息里带上腾讯的 `result` 与 `err_msg`
  原文；只翻译成人话会让唯一线索消失。同样地，`result:1003` 不再一律当成
  登录过期——`wrong scene` 是我们自己的参数错，让用户重扫一百次也没用。

## [0.1.0] - 2026-10-13

首个版本。

### 新增

- **QQ 扫码登录**（`aiva/auth/ptlogin.py`）：出码 → 轮询 → 从 `auth://` 回调取
  `openid` 与 `access_token` → `app.mval.qq.com/go/auth/login_by_qq` 换 `userId`
  与 `tid`。全流程纯 HTTP，不需要浏览器侧车。
- **`/爱瓦 战绩`**：近期战绩聚合。胜负与胜率、场均 K/D/A、KDA、场均 ACS、
  场均回合净胜、最近走势、地图分布、常用特工。
- **`/爱瓦 锐评`**：模型写一段锐评，先给一句称号，再说打得好／问题／建议。
- **`/爱瓦 PK @群友`**：和另一个**已绑定**的人比。八项逐项对比由代码算死再交模型
  解说（「让模型自己比」的实测结果是端水话），模型只负责打分与解说。
- **`/爱瓦 开一局`**：随机生成一局竞技模式让模型推演。胜负按他自己的胜率抽，
  且**无论输赢都可能打出高 ACS**——回合制里「虽败犹荣」很常见。
- **`/爱瓦 解绑`**：删本地凭据文件。
- **落空兜底**：`/爱瓦 <不是子命令>` 时插件自己回提示，不放给模型编。

### 设计要点

- **字段白名单写进提示词。** 掌瓦列表没有 ADR、KAST、经济、攻防回合、
  命中率分布、武器明细、队友信息。必须明确告诉模型这些没有，否则它会照着
  别的 FPS 的指标体系编答案——这是爱完美踩过的坑。
- **地图与特工中文名取自 Riot 官方接口** `valorant-api.com`
  （`/v1/maps`、`/v1/agents`，`?language=zh-CN`）。凭记忆写错过一次：
  四个是错的（亚述／霜寒城谣／莲华／日落城），一个干脆是编的（禁地龛境）。
  正确的一组是：亚海悬城、霓虹町、裂变峡谷、源工重镇、微风岛屿、盐海矿镇、
  深海明珠、森寒冬港、莲华古城、日落之城、幽邃地窟。
- **凭据不进日志。** `扫码结果.__repr__` 只给 openid 长度，
  `storage.凭据摘要` 只给 userId 的前后各几位。

### 修正

- 修掉一个**只在容器加载时才暴露**的问题：`_取近期战绩` 在同一函数里既要
  `yield` 错误提示、又要 `return (文本, 摘要)`，触发
  `SyntaxError: 'return' with value in async generator`——AstrBot 导入插件
  直接失败并把插件卸掉。本地 `pytest` 一行都跑不到这条路径。改成抛
  `这句给用户`，并补了 `test/test_main_structure.py` 把这条钉住。

### 说明

- 工程配置、`.gitattributes` 排除项与发布流程照 `astrbot_plugin_aiwm`
  拉平，两个插件保持同一套 CI 门禁。
- 图标：源图 `icon/aiva-icon.png`（用户绘制），经 `test/做图标.py` 生成
  256×256 的 `logo.png`。这张源图**不做亮度抠底**——图案暗部与背景亮度
  重叠（背景 r+g+b 40~57，人物面部阴影 55、红圈暗部 66），按亮度抠会把
  人物抠没；徽章外圈约占画布 87%，圆形裁切切不到图案，直接整张缩放。
  与 aiwm 那份脚本路线不同，原因写在脚本注释里。
